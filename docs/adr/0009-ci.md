# ADR-0009: Continuous Integration

**Status:** Proposed
**Date:** 2026-10-08
**Confidence:** Medium
**Supersedes:** none
**Superseded by:** none

## Context

The assessment requires automated tests and a way to run them. A hosted pipeline is useful once those tests exist. Deploying the applications is not required. This record is not implemented until the phase gate in [guardrails.md](../guardrails.md) has passed.

## Options Considered

### Option 1 — GitHub Actions runs PHPUnit and the Angular test or build

Selected when this record is accepted. A push fails when the required checks fail. There is no deploy job.

### Option 2 — A deploy pipeline to cloud infrastructure

Rejected. The assessment does not ask for a hosted environment, and the time box should stay on the working flow.

### Option 3 — Local test commands only

Acceptable through Phase 1. The README must still explain how to run PHPUnit, the queue worker, and the Angular checks.

## Decision

Proposed: add `.github/workflows/ci.yml` after Phase 1 is green locally. The workflow installs dependencies and runs the Laravel tests and the Angular test or production build. It does not deploy.

This record does not authorise adding CI before the phase gate.

## Consequences

### Positive

- A later push shows that the same checks run outside one machine.
- The pipeline stays small enough to explain.

### Negative

- CI needs a MySQL or sqlite test database strategy and will fail if the tests assume a machine-specific setup.
- It does not prove the queue worker was run by hand against a real campaign.

## Tradeoffs

Local tests remain the Phase 1 proof. CI is a repeat of those checks, not a substitute for the manual campaign flow in [engineering-rules.md](../engineering-rules.md).
