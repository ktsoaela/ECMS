# ADR-0009: Continuous Integration

**Status:** Accepted
**Date:** 2026-10-08
**Accepted:** 2026-10-09
**Confidence:** Medium
**Supersedes:** none
**Superseded by:** none

## Context

The assessment requires automated tests and a way to run them. A hosted pipeline is useful once those tests exist. Deploying the applications is not required. The [phase gate](../guardrails.md) has passed.

## Options Considered

### Option 1 — GitHub Actions runs PHPUnit and the Angular production build

Selected. A push fails when the required checks fail. There is no deploy job.

### Option 2 — A deploy pipeline to cloud infrastructure

Rejected. The assessment does not ask for a hosted environment.

### Option 3 — Local test commands only

Rejected after the phase gate. Local commands remain documented in the README; CI repeats them on every push.

## Decision

Add `.github/workflows/ci.yml`. The workflow installs dependencies and runs the Laravel PHPUnit suite (sqlite in-memory, matching `phpunit.xml`) and `ng build` for the Angular app. It does not deploy.

## Consequences

### Positive

- A later push shows that the same checks run outside one machine.
- The pipeline stays small enough to explain.

### Negative

- CI does not prove the queue worker was run by hand against a real campaign.
- Angular unit tests are optional; the workflow uses the production build as the frontend check.

## Tradeoffs

Local tests and the manual campaign flow in [engineering-rules.md](../engineering-rules.md) remain the primary proof. CI is a repeat of those automated checks, not a substitute for the worker smoke path.
